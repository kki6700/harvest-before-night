# Lantern Harvest — 개발 기록 (2차 Unity 평가)

## 10/22 씬 구성
- 새 프로젝트 `02_Unity_Eval` (Unity 6000.3.24f1, URP). 1차에서 만든 개인 프로젝트(DSEWA_63)의 설정 · 아트를 GUID 그대로 복사, 팀 프로젝트에서 직접 만든 작물(등불 열매 3단계 · 버섯꽃 3종 · 공용 성장 애니메이션)과 최신 셰이더만 추가.
- 문제 1: 팀 작물 일부가 1차 에셋을 이름만 바꾼 복사본이라 GUID가 겹침 → Unity가 한쪽에 새 GUID를 붙여 프리팹 머티리얼 68개가 빈칸이 됨. 겹치는 옛 파일을 지우고, 남긴 파일을 프로젝트 밖으로 뺐다 다시 넣어 원래 GUID로 등록되게 해서 해결.
- 문제 2: 지형 데이터 `TD_LookDev.asset`이 더 최신 Unity(6000.6)에서 저장돼 열리지 않음 → 씬은 이미 `TD_LookDev_DeepBlue`를 쓰고 있어 영향 없음 확인.
- `Stage1` 씬: 배경 씬(하늘 · 구름 · 지형 · 안개 · 크리스탈 · 버섯 · 호수 · 낮/밤 전환)을 바탕으로 테스트 물체 정리, 밭 6개(4 × 4 m, 칸 24) + 등불 열매 · 버섯꽃(완성 / 자라는 중 섞음), 플레이어 = SD 고양이(Idle / Walk / Run 애니), 3인칭 카메라, 시작 시각 오후 2시.
- 외계인 손님(Cunsumer, 1차 직접 제작: 얼굴 리토폴 · 옷 · 21본 리그 · Mixamo 걷기 · 툰 셰이더)을 납품 상대로: 가게 문 · 손님 · 바구니를 함께 밭 오른쪽 옆(문 (12.5, 0, -6.5))으로 옮기고 플레이어 시작점 쪽을 보게 돌림. 처음 (9.5, 0, -1.5)은 밭과 겹쳐서 다시 옮김.
- 콘솔 에러 정리: (1) 1차 · 팀 복사본이 같은 GUID를 가진 파일 7개(꽃 등불 열매 모델 · 재질, 수확 아이템)가 Unity DB에서 다른 GUID로 등록돼 배경 씬 프리팹이 끊김 → 폴더를 잠깐 빼고 다시 넣어 원래 GUID로 재등록, 프로젝트 전체 DB/meta GUID 불일치 0 확인. (2) 열리지 않는 6000.6 지형 파일 2개(안 쓰임) 삭제. (3) URP 전역 설정에 남은 최신 URP 전용 타입 6개 제거(ClearAllManagedReferencesWithMissingTypes). (4) 셰이더 Properties의 Header 문구에 쉼표 · 괄호가 있어 drawer 생성 실패 → 영문자 · 숫자만 남김. 처음에 -, / 로 바꿨다가 셰이더 13개가 파싱 에러(이름 빈칸, 지형이 안 그려짐) → 원본으로 되돌리고 다시 정리. (5) ToonFoliage 경고(조기 return으로 초기화 안 된 변수) → if 블록으로 바꿈. (6) 구름 3D 텍스처 이름 불일치 수정. 플레이 모드 에러 · 경고 0.

## 10/22 플레이어 · 수확 (AI 코딩: Claude Code)
- 요청(프롬프트): "고양이가 입에 바구니 손잡이 물고 가까이 가서 따는 걸로" / "잔디가 밭을 뚫는 문제도 해결".
- 스크립트(Assets/Scripts/Gameplay): `CatController`(WASD · Shift 달리기, 카메라 기준 이동, CharacterController, 상태 이름으로 Idle/Walk/Run 재생), `FollowCamera`(뒤 위 3인칭, 우클릭 드래그 회전 · 휠 줌), `RipeCrop`(익은 작물: 등불 열매는 Animator 트리거 Harvest/Regrow, 버섯꽃은 크기 줄였다 다시 자람), `CatHarvester`(가까운 익은 작물 찾기 → E/Space로 수확: 멈추고 작물 쪽으로 돌아 고개를 숙였다 들고, 열매가 포물선으로 바구니에 들어감, 정원 12), `BasketFill`(바구니 안 열매 90개를 아래부터 채워 보이기), `DeliveryPoint`(외계인 손님 납품).
- 바구니: 1차에서 만든 `CarriedBasket`(손 소켓 + 진자 흔들림)을 재사용, 손 대신 고양이 입 뼈(mouth_mid) 앞 16 cm `MouthGrip`에 손잡이를 걸고 0.42배.
- 오류 1: `HarvestableCrop.cs`만 컴파일 목록(Assembly-CSharp.rsp)에서 빠져 CS0246 → meta 재생성 · 강제 재컴파일로도 안 돼서 파일 · 클래스 이름을 `RipeCrop`으로 바꿔 해결.
- 오류 2: `??` 연산자로 컴포넌트를 가져오다 MissingComponentException (Unity 오브젝트의 가짜 null) → `if (x == null)`로 변경.
- 오류 3: 플레이 중 고양이가 땅을 뚫고 -600 m까지 떨어짐 → 원인은 물리 충돌 매트릭스에서 Default-Default 충돌이 꺼져 있던 것(1차 프로젝트 설정). 다시 켬.
- 잔디: 지형 잔디 생성기(LayerGrassSpawner)의 제외 영역에 밭 6개 · 가게 문 앞 박스를 넣고 다시 생성 → 밭 안 잔디 0.
- 미끄러짐(사용자: "고양이 동작이 크지 않아서 미끄러지는 것 같아"): 걷기 클립의 발끝 이동을 재 보니 한 주기(1초)에 6 cm → 미끄러지지 않으려면 초속 0.12 m. SD 체형이라 걸음으로는 게임 속도를 못 냄 → **통통 뛰는 이동**으로: 이동 거리에 맞춰 몸(CTRL_root)이 포물선으로 뜨고(걷기 0.42 m마다 7 cm, 달리기 0.75 m마다 12 cm), 착지 직후 살짝 눌림 · 앞으로 8° 기울기, 다리 애니 재생 속도 2.2배(달리기 1.8배), 이동 속도 1.8 / 3.4 m/s. 값은 내 값.
- 오류 4: 시험 녹화에서 고양이 메시가 화면 밖 수십 m로 날아감 → 원인: Animator는 값이 안 바뀐 커브의 뼈를 매 프레임 다시 쓰지 않아서, LateUpdate에서 더한 점프 오프셋이 누적됨. 지난 프레임에 쓴 값이 그대로면 깨끗한 포즈로 되돌린 뒤 다시 더하도록 수정.
- 확인용 `FrameRecorder`(카메라 → PNG 프레임) 추가: 키 입력 없이 디버그 입력으로 이동시키고 녹화.
- 달리기 모션(사용자: "블렌더에 달리는 모션도 있을 텐데 그거 가져와"): 열려 있는 SDCat.blend의 액션을 확인 → SDCat_Run(17프레임, 24 fps)이 Unity에 이미 들어온 클립과 같음. 걷기 클립(발 6 cm · 머리 흔들림 1.3 cm)보다 다리(8.7 cm) · 머리(4.1 cm) 움직임이 큰 이 달리기 사이클을 걷기 · 달리기 모두에 쓰고 재생 속도만 1.3배 / 1.9배로 나눔.
- IK/FK 리깅(사용자: "미사르에 가져와서 다시 IK FK 제대로 리깅하지"): SDCat.blend를 Mixar 새 장면 탭(SDCat_Rig)으로 가져옴 → 리그 확인: 다리가 뼈 하나(16 cm)라 진자처럼만 흔들림. Mixar의 렌더 확인 기능이 응답하지 않아(async_render_unavailable) 같은 Blender 엔진을 백그라운드로 돌려 스크립트로 작업 · 렌더 확인하고, 결과 파일을 다시 Mixar 탭에 불러옴.
  - `rig_sd_cat_ikfk.py`(DSEWA_63/Art/SDCat/scripts): 다리마다 위 · 아래 두 마디 변형 뼈(<leg>, <leg>_lower, 무릎 뒤로 2.5 cm 굽힘), 다리 가중치를 높이에 따라 두 뼈로 나눔(무릎 주변 35 % 폭 부드럽게), IK 발 컨트롤(IK_<leg>, CTRL_root 자식 → 몸이 움직여도 발 고정) + 무릎 폴(POLE_<leg>), CTRL_root의 사용자 속성 `ik_<leg>`(1 = IK, 0 = FK)가 드라이버로 IK 영향도 제어, 컨트롤 모양(원 · 마름모). 폴 각도는 쉼 자세가 안 변하는 값을 자동 탐색(90°).
  - `anim_sd_cat_run_ik.py`: IK 발로 새 달리기(12프레임 0.5초, 발 55 % 땅에 붙음, 앞 · 뒤 쌍 반 주기 차이, 몸 한 번 뜀 · 숙임 · 착지 눌림, 머리 반대 숙임, 귀 · 꼬리). 다른 동작에는 새 뼈 쉼 자세 키를 넣어 FBX 내보낼 때 보폭 자세가 남지 않게 함.
  - 기존 `export_sd_cat_fbx.py`로 다시 내보내 Unity SDCat.fbx 교체(같은 GUID, 프리팹 자동 갱신, 하체 뼈 4개 추가 · 빠진 뼈 0). 달리기 재생 1.6배 / 2.2배.
- 웨이트 다듬기(사용자: "웨이트 페인트 좀 잡아서 자연스럽게"): 달리기 프레임을 다리 가까이 렌더해 보니 (1) 발바닥이 위 · 아래 두 뼈에 섞여 무릎이 접힐 때 구겨지고 (2) 엉덩이 · 어깨 이음새가 한 줄 안에서 급하게 꺾임. `weights_sd_cat_legs.py`: 다리 아래 32 %(발)는 아래 뼈만 따르게(단단한 발), 무릎 섞임은 다리 길이 30 % 폭에서 부드럽게, 다리 전체 몫을 엉덩이 근처(반경 0.17)에서 6번 이웃 평균으로 퍼뜨리고 몸통 뼈가 나머지를 받아 합 1 유지. 
- 그런데 전후 비교 렌더가 거의 같아서 원인을 다시 봄 → 구겨짐의 대부분은 웨이트가 아니라 **스윙하는 발이 배 속으로 파고드는 것**(다리 0.16에 발 들기 0.075). 발 들기 0.045 · 보폭 ±0.09로 줄이고 스윙 때 발을 3 cm 바깥으로 벌림. 발에 남아 있던 몸통 가중치도 0으로(발바닥 당김 제거). 수치는 내 값. 비교 이미지 14.
- 뒷발 가중치 키움(사용자: "뒷발 가중치를 좀 더 높게"): 뒷다리는 엉덩이 관절 반경 0.26 안에서 다리 몫을 최소 0.75 × 부드러운 감쇠로 올려(허벅지 · 엉덩이 살이 다리를 따라 움직임) 그 뒤 이웃 평균으로 퍼뜨림. 가중치 색 지도 전후 비교 15(빨강 = 뒷다리).
- 앞발 역관절(사용자: "역관절 느낌 나게 앞발에 뼈 추가"): `add_front_paw_sd_cat.py` — 앞다리를 위 → 아래 → 발(손목) 세 마디로, 손목은 아래 뼈의 45 % 지점, 발 뼈는 발끝 쪽으로 6 cm. IK는 손목을 노리도록(IKT_ 대상, 발 컨트롤 자식). 달리기에서 발 뼈 회전 키: 딛는 동안 평평, 딛기 끝에 뒤꿈치 20° 들기, 들어 올릴 때 발끝을 65° 뒤로 접음. 웨이트: 손목 둘레 14 % 폭에서 아래다리 → 발로 넘어감.
  - 오류: 처음엔 발 뼈가 발 컨트롤 회전을 따라가게 Child Of 제약을 썼더니 발이 앞으로 늘어나고 다리에서 떨어져 나감 → 제약을 빼고 아래다리에 바로 붙인 FK 뼈로 바꾼 뒤 키로 꺾음. 이미지 16.
